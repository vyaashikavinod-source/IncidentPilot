What these numbers mean

The base model and IncidentPilot investigations used the publisher's Qwen2.5-1.5B-Instruct-GGUF Q4_K_M on local CPU / llama.cpp. The shared process peaked at 2.08 GB of working-set memory. The trained pilot used FP16 plus a QLoRA adapter on a Colab T4. Its inference GPU snapshot was 3,583 MiB (whole GPU, not isolated peak model memory). Training peak allocated VRAM was 9.22 GB. Quantized serving used four CPU threads; its Windows server process peaked at 1.89 GB working set, including loading and warmup. Hardware, precision, chat formatting and caching differ, so timings are descriptive, not a controlled before/after speedup.

API token charges and Colab GPU spending were $0. Hardware and electricity are not included. The 64-clause training run is a pilot, not a final release. The free Gemini API attempt stopped after three consecutive service errors; its partial journal is included in the downloads. No completed frontier API comparison or public model-host latency has been measured. Visiting this page replays evidence and does not run the model.
